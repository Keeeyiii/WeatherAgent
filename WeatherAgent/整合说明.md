## 一、我对你原项目的分析

我读完了 `legacy/` 下的全部代码（1 个主程序 + 4 个工具模块 + 1 个 Agent 模块）。结论如下。

### 做得好的地方

1. **结构分层清楚。** `app.py` 只负责界面，计算放在 `tools/`，LLM 调用放在 `agent/`。
   这个分法是对的，后面的扩展都建立在它之上。
2. **愿意做基线对比。** 你没有只报告随机森林的成绩，而是主动加了"常数去偏"和"按小时去偏"
   两个基线。这是很多人不会做的事。
3. **如实写局限。** README 里明确写了"数据属于演示数据""随机森林没有超过基线 B"。
   正因为你写了这句，问题才有了被定位和解决的机会。
4. **Agent 的规则设计很克制。** 系统提示里 12 条规则，核心是"所有数值必须来自 Python 工具，
   不允许编造"。这条原则我完整继承下来了。

### 三个真实存在的问题

**问题 1：数据是合成的，这让结论无法成立。**

`legacy/data/sample_weather.csv` 是 240 行模拟数据（2026-01-01 起 10 天）。
合成数据里"日变化"信号是人为设进去的，所以模型只要抓住 `hour` 这个特征就能拿高分——
README 里 `hour` 的特征重要性高达 0.77，正是这个原因。
更关键的是：合成数据让简单基线也能轻易取胜，于是"随机森林输给按小时去偏"
这个结论反映的是**数据的性质**，而不是模型的能力。

**问题 2：最优插值的权重用错了位置。**

`legacy/tools/oi_correction.py` 的核心是：

```python
w = sigma_b² / (sigma_b² + sigma_o²)      # ≈ 0.9
analysis = forecast + w * mean_bias       # 平均偏差 × 0.9
```

这不构成最优插值。真正的 OI 是

$$x_a = x_b + B H^\top (H B H^\top + R)^{-1} (y - H x_b)$$

**权重作用在"空间观测新息（y − Hx_b）"上，而不是作用在"时间平均偏差"上。**
把平均偏差乘一个小于 1 的权重，等价于把常数去偏打了九折——
所以它必然比"常数去偏"基线差，这也是预期之中的结果。

问题不在"想到了用 OI"这个方向（方向非常对），而在于公式的落点。

**问题 3：`__pycache__` 被提交进了仓库。**

这只是小事，新的 `.gitignore` 已经排除。

## 三、保留了什么

为了让概念能直接衔接，以下约定**完全沿用**你的版本：

- 误差定义 `error = forecast − observed`，正值表示偏暖；
- 六个特征：预报气温、湿度、气压、风速、小时、月份；
- 订正量的定义：模型预测误差本身，然后 `corrected = forecast − predicted_error`；
- 数据文件的列名（`time, forecast_temperature, observed_temperature, humidity,
  pressure, wind_speed, hour, month`），因此新数据可以直接替换旧 CSV；
- 页面主线：数据检查 → 误差评价 → 机器学习订正 → AI 助手；
- **Agent 的核心分工原则**：数值全部由 Python 计算，语言模型只负责理解问题和组织语言。

# WeatherAgent · 真实数据版

**用 2.4 年真实观测检验 GFS 2 米气温预报，并回答一个具体问题。**

> 这一版与早期版本的关系、以及每一处改动的理由，见 [整合说明.md](整合说明.md)。
> 早期代码完整保存在 [legacy/](legacy/)。

本项目是一个气象数据分析应用（科研实践原型），不做"AI 天气预报"，
而是聚焦一个可以被数据回答的小问题：

> GFS 对南京 2 米气温的预报误差，是随机噪声，还是有结构的系统性偏差？
> 如果是结构，它长什么样？能被订正吗？

---

## 一句话结论

误差的核心不是"偏暖"或"偏冷"，而是**模式压扁了温度的变幅**：

- 日较差被系统性低估 **16%**（观测 9.18 ℃ → 预报 7.68 ℃），冬季压缩最严重，只剩 66%；
- 误差与观测距平成反比：`误差 = −0.21 − 0.14 × 观测距平`（r = −0.26），
  **天越冷模式越偏暖，天越热模式越偏冷**；
- 最冷 1% 的时刻平均偏暖 **+4.35 ℃**，最暖 1% 的时刻平均偏冷 **−2.19 ℃**；
- 因此"减去平均偏差"式的订正几乎无效（仅改善 0.6%），
  而随机森林可把 MAE 从 **1.58 ℃** 降到 **1.22 ℃**（改善 22.8%）。

## 数据

**全部为真实数据，项目内不含任何合成数据。**

| 用途 | 内容 | 来源 |
|---|---|---|
| 观测（真值） | 南京禄口 ZSNJ 逐小时地面观测 | Iowa Environmental Mesonet（METAR 归档） |
| 预报 | GFS 2 米气温历史预报 | Open-Meteo 历史预报归档 |
| 预报时效 | GFS 1/2/3/5/7 天预报 | Open-Meteo previous-runs 归档 |
| 对照站 | 上海虹桥 ZSSS 逐小时观测 | Iowa Environmental Mesonet |

样本规模：**23,543 个有效"预报—观测"配对小时**，时段 2024-01-01 至 2026-09-15。

## 快速开始

```bash
pip install -r requirements.txt
streamlit run app.py
```

应用读取仓库内已内置的 CSV，**离线即可运行**，不需要任何 API Key。

**要把应用变成可以发给导师的公开链接，请看 [部署指南.md](部署指南.md)**（全程不需要命令行）。

**只有半页时间的读者，看 [成果速览.md](成果速览.md) 即可。**

**完整的书面研究报告见 [研究报告.md](研究报告.md)**，也可直接打开
[研究报告.html](研究报告.html) 用浏览器打印成 PDF（图片已内嵌，无需联网）。

### 重新抓取数据（可选）

```bash
python tools/real_data.py           # 从公开数据源重新下载观测与预报
python analysis/run_verification.py # 跑完整分析并导出所有结果表
```

### 部署到 Streamlit Community Cloud

1. 把本文件夹内容推送到 GitHub 仓库；
2. 打开 [share.streamlit.io](https://share.streamlit.io) → New app → 选择仓库与 `app.py`；
3. Deploy。**不需要配置任何 Secrets**——应用默认使用离线助手。

## 主要结果

### 1. 总体检验（南京，2024-01 至 2026-09）

| 指标 | 数值 |
|---|---|
| 平均偏差 bias | −0.21 ℃ |
| MAE | 1.58 ℃ |
| RMSE | 2.12 ℃ |
| 相关系数 | 0.983 |

### 2. 订正方法消融（三折严格时序验证，MAE 均值 ± 折间标准差）

| 方法 | MAE | 相对原始改善 | 本层新增改善 |
|---|---|---|---|
| ① 原始预报 | 1.586 ± 0.076 | — | — |
| ② 常数去偏 | 1.578 ± 0.100 | +0.6% | +0.6% |
| ③ 按月去偏 | 1.390 ± 0.162 | +12.4% | +11.9% |
| ④ 按小时去偏 | 1.571 ± 0.077 | +0.9% | （对照项） |
| ⑤ 按(月×小时)去偏 | 1.315 ± 0.143 | +17.1% | +16.1% |
| ⑥ 随机森林 | **1.225 ± 0.232** | **+22.8%** | +5.7% |

**关键读法**：随机森林在最强基线上只额外贡献 5.7 个百分点，
说明订正收益的**大部分来自消除系统性结构**，而非复杂的非线性关系。
同时它的折间标准差最大，稳定性不如简单方法——这是真实的权衡。

### 3. 跨站点迁移检验（南京训练 → 上海测试）

| 方法 | 上海 MAE | 相对上海原始改善 |
|---|---|---|
| ① 原始预报 | 1.062 | — |
| ⑤ 按(月×小时)去偏 | 1.076 | −1.3% |
| ⑥ 随机森林 | 1.182 | **−11.2%** |

**所有订正方法都失效。** 原因：上海原始误差本就小得多，
且几乎不存在振幅压缩问题（日较差比值 0.98，南京 0.84）。
这说明统计订正模型高度依赖站点，不能简单推广。

## 设计原则

1. **只用真实数据。** 合成数据可以让任何模型看起来都很好。
2. **严格时序划分。** 误差滞后 1 小时自相关高达 0.90，随机划分会严重高估模型能力。
3. **嵌套消融而非模型竞赛。** 问"收益来自哪一部分误差"，而不是"我的模型提升多少"。
4. **做可证伪的检验。** 跨站点迁移实验是主动为"振幅压缩"解释设置的反例测试。
5. **记录被推翻的假设。** 一个结论的可信度，取决于它是否经受过检验。

---

## 已知局限

- 主站点仅南京，另加上海作对照，结论不能推广到全国；
- 中国机场 METAR 不报降水量，无法开展降水检验（需 IMERG / CHIRPS 等卫星产品）；
- 观测为机场站点、预报为格点值，存在代表性误差；
- 仅检验 2 米气温；
- 时效数据仅覆盖最近 92 天；
- 纯统计订正缺乏物理约束，外推能力有限。

详见应用内"局限与展望"页。
